# Incremental roadmap

This roadmap implements the greenfield master brief expressed in the [README](../../README.md) and [charter](../business/project-charter.md). It does not inherit a hackathon challenge sequence and is separate from Agentic SDLC work. **Milestones 1–9 are delivered within their recorded scope; Milestones 10–17 are PLANNED and not started.** Runtime evidence comprises the Python foundation, offline dataset tools, simulated-fixture benchmark, local structured-evidence validation/admission, draft-policy lexical retrieval, authored-query evaluation and non-binding provisional rule findings, not a processing service or live model evaluation. Each milestone ends with reviewable evidence and an explicit status update.

Security, tests, provenance, basic telemetry and cost limits start with their first relevant component; later milestones deepen them rather than defer all controls. No milestone is complete solely because code exists. Actual Azure calls in any milestone require separate deployment/spending authorization; local progress uses explicitly labeled simulations where necessary.

Working definitions: **IMPLEMENTED** means an artifact/code path exists; **TESTED** adds a named environment and recorded checks/results; **SIMULATED** means a stub or injected scenario exercised a contract without proving the live dependency; **PLANNED** means intended only. Track capability and environment separately; documentation completion never promotes runtime status.

Approved requests govern scope: M2 delivered the foundation, M3 baselined requirements, M4 added the corpus, M5 benchmarked fixture extraction, M6 validated evidence, M7 delivered lexical policy knowledge, M8 measures it against authored queries, and M9 adds explicitly unapproved non-binding rule findings. Remaining intake/scanning/API/persistence work moves to M10 and subsequent planned work to M11–17. M7–M9 do not complete M11's approved policy publication/resolution, hybrid retrieval or operational rule engine. M8's four lexical failures remain unresolved; labels, wording and any operational rule release need independent owner review. These are sequencing changes only; historical milestone records retain their then-current plans. Contracts and architectural authority boundaries are preserved; see [M9 evidence](milestone-9.md).

Next proposed action after M9 review: independently review provisional terms, source-linked classification assumptions and the unresolved M8 failures; separately approve bounded intake/scanning/persistence scope for M10. No M10 implementation, live provider integration or operational rule publication has started. Git setup/connection/commits remain manual and separate.
