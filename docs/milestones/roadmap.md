# Incremental roadmap

This roadmap implements the greenfield master brief expressed in the [README](../../README.md) and [charter](../business/project-charter.md). It does not inherit a hackathon challenge sequence and is separate from Agentic SDLC work. **Milestones 1–21 are delivered within their recorded local/reference scopes. M22 Stage B implements offline engineering infrastructure; independent held-out approval and production acceptance remain pending. M23 container deployment is DEFERRED — SECURITY GATE NO-GO; Stage A/B1 preparation and later artifact/security evidence retain their scoped results. Milestone 24 is OFFLINE DOCUMENTATION COMPLETE / EXECUTION BLOCKED / DEPLOYMENT NO-GO; all six demonstrations remain NOT_TESTED, as recorded in the [consolidated M24 report](milestone-24.md).** Runtime evidence comprises the Python foundation, offline dataset tools, simulated-fixture benchmark, local structured-evidence validation/admission, draft-policy lexical retrieval, authored-query evaluation and non-binding provisional rule findings and actual framework execution and governed internal tools and deterministic offline workflow/checkpoints plus real local MCP client/server transport; model behavior remains simulated; it does not establish a processing service or live model evaluation. Each milestone ends with reviewable evidence and an explicit status update.

Security, tests, provenance, basic telemetry and cost limits start with their first relevant component; later milestones deepen them rather than defer all controls. No milestone is complete solely because code exists. Actual Azure calls in any milestone require separate deployment/spending authorization; local progress uses explicitly labeled simulations where necessary.

Working definitions: **IMPLEMENTED** means an artifact/code path exists; **TESTED** adds a named environment and recorded checks/results; **SIMULATED** means a stub or injected scenario exercised a contract without proving the live dependency; **PLANNED** means intended only. Track capability and environment separately; documentation completion never promotes runtime status.
