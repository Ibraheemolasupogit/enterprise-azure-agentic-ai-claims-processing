# Incremental roadmap

This roadmap implements the greenfield master brief expressed in the [README](../../README.md) and [charter](../business/project-charter.md). It does not inherit a hackathon challenge sequence and is separate from Agentic SDLC work. **Milestones 1–6 are delivered within their recorded scope; Milestones 7–14 are PLANNED and not started.** Runtime evidence comprises the Python foundation, offline dataset tools, simulated-fixture benchmark and local structured-evidence validation/admission, not a processing service or live model evaluation. Each milestone ends with reviewable evidence and an explicit status update.

| Milestone | Scope and expected deliverables | Exit evidence |
| --- | --- | --- |
| 1 — Charter and architecture baseline | Business scope, architecture/security, evaluation/deployment strategies, roadmap and `.gitignore` | Document/link/consistency checks; no runtime claims |
| 2 — Python engineering foundation | Versioned claim/evidence/policy/assessment/review models; deterministic transitions; local settings/redacted logs; typed protocols; packaging and quality tooling | Local unit tests, lint/format, strict typing and package checks; synthetic examples only; no API, persistence or policy engine |
| 3 — Business process and architecture refinement | Manual/target workflow, role responsibilities, stable requirements/acceptance, traceability, risks and essential ADR | Documentation/link/symbol/status consistency; no runtime changes or new test-run claim |
| 4 — Synthetic motor claims dataset and ground truth | Seeded PDF/PNG fixture authoring, 12 development scenarios, draft policy versions, typed source-linked annotations and integrity/reproduction checks | Unit/lint/type checks, exact regeneration and readable-artifact verification; no approved coverage outcomes or live processors |
| 5 — Document intelligence benchmark foundation | Common extraction DTOs/vendor protocols, deterministic field scoring, clean failures, capability cohorts, CLI and simulated oracle fixture | Unit/lint/type/package checks, identical offline reports and preserved M4 corpus; no live provider implementation or performance comparison |
| 6 — Structured claims evidence processing | Typed extraction mapping, source/hash/ownership validation, normalization, quality holds, immutable local history, guarded in-memory admission and offline CLI | Unit/lint/type/package checks, preserved M4/M5 semantics, identical simulated reports; no original case admission, scanner, service or persistence |

| 14 — Readiness and portfolio evidence | End-to-end synthetic demonstration, restore/recovery exercise, architecture reconciliation, limitations and teardown plan | Traceable implemented/tested/simulated/planned matrix; evaluation, security and operational reports; no unsupported production-readiness claim |

Security, tests, provenance, basic telemetry and cost limits start with their first relevant component; later milestones deepen them rather than defer all controls. No milestone is complete solely because code exists. Actual Azure calls in any milestone require separate deployment/spending authorization; local progress uses explicitly labeled simulations where necessary.

Working definitions: **IMPLEMENTED** means an artifact/code path exists; **TESTED** adds a named environment and recorded checks/results; **SIMULATED** means a stub or injected scenario exercised a contract without proving the live dependency; **PLANNED** means intended only. Track capability and environment separately; documentation completion never promotes runtime status.

Approved requests govern scope: M2 narrowed delivery to foundation code, M3 added business/architecture documentation, M4 added the development corpus, M5 added the offline benchmark and M6 delivered structured-evidence validation before the broader ingestion service. Remaining intake/scanning/API/persistence work moves to M7 and subsequent planned work to M8–14. Draft wording/schedules still require policy-owner approval before rule execution. These are sequencing changes only; historical milestone records retain their then-current plans. Contracts and architectural authority boundaries are preserved; see [M6 evidence](milestone-6.md).

Next proposed action after M6 review: approve the bounded intake/scanning/persistence service scope and trusted source-index contract for M7. No live provider implementation or M7 work has started. Git setup/connection/commits remain manual and separate.
