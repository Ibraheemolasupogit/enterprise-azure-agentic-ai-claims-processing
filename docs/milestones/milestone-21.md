## Compatibility and remaining limits

M21's code additions change whole-package M12/M20 runtime fingerprints. Historical M20 databases/checkpoints are intentionally rejected by this runtime; schema v1 is unchanged and no migration or history rewrite is implemented. Fresh same-runtime recovery requires independently retained public verification context, lifecycle integrity key/latest rollback anchor, approved sources and canonical host sessions. Disabled actors remain independently known for audit replay while current grants are denied.

HMAC/SQLite are bounded local trusted-host controls, not WORM, power-loss/cloud durability or shared directory revocation. Anchors need independent current custody; stale anchors cannot detect every newer revocation rollback. Checks occur at admission, not atomically with a second case DB or cancellation of in-flight work. Browser cookies and opaque capabilities are reprovisioned, never recovered. Fixture validation cannot authenticate actual humans/workloads and cannot be used as Entra sign-in. Deployment checks and APIM policies remain static references; no live security enforcement is claimed. Reliable security audit delivery/retention, distributed revocation, real browser/TLS/provider integration and operational readiness remain future work.

Historical M4–M9 data/evaluations, M8 Q-007/Q-012/Q-015/Q-029, M12 timing sensitivity and prior milestone evidence remain preserved. The original eight M19 NOT_TESTED classifications are unchanged. No commits or pushes; stop after M21 for review.


**Acceptance recommendation: ACCEPT M21 within the explicitly requested offline synthetic scope.** No live Entra, deployed gateway, cloud security, actual human identity or production-risk acceptance is implied. All prior security boundaries remain and no M22 implementation has begun.

The expiry check can be reproduced without altering fixtures (use the installed M21 package or `PYTHONPATH=src`):

```python
from pathlib import Path
from claims_ai.security_hardening.contracts import IdentityClass
from claims_ai.security_hardening.providers import load_fixture

for kind in IdentityClass:
    verifier, token = load_fixture(str(Path("data/security/identity/v1") / f"{kind.value}.json"))
    epoch = verifier._clock()  # Explicit synthetic test-clock override, never live-provider mode.
    verifier._clock = lambda: epoch + 299
    assert verifier.verify(token) is not None
    verifier._clock = lambda: epoch + 300
    assert verifier.verify(token) is None
```
