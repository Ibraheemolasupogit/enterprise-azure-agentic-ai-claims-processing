# Offline quality and operational observability — M22 Stage B

Status: implemented local engineering scope; independent quality and production acceptance remain pending. The preserved [Stage A contracts](../quality/m22-stage-a-contracts-and-holdout.md) and candidate bytes are authoritative for the proposed holdout. Stage B does not authenticate an independent reviewer or release a benchmark.

## Evaluation boundary

`quality_ops.evaluation` verifies the externally pinned candidate manifest and reports all 60 cases, distributed 15/10/10/10/10/5, as PENDING_REVIEW / NOT_TESTED. No prediction is requested for them. Trusted coordination reads reference roster/cohort metadata only after verification; reference labels never enter the prediction worker. `require_independent_scoring` always rejects: an approval flag, signature string, file or hash is not an authenticated review. There is no CLI override.

Six new DEV cases and their hand-authored reference module are separate from frozen candidates. Inputs contain only bounded native text and development IDs. A fresh `python -I -B` worker imports the fixed parser, receives inputs through stdin and emits validated bounded predictions. It imports neither reference module. This is a trusted local code/import boundary, not a hostile-code filesystem sandbox. Author-visible conformance is SIMULATED_DEVELOPMENT_NOT_INDEPENDENT; it establishes no model, OCR, multimodal, policy or insurance accuracy.

Each case retains five eligible critical fields. Missing predictions remain failures in that denominator; missing expected values are compared explicitly. Wrong/duplicate case IDs and invalid prediction schemas are rejected. Harness errors are NOT_TESTED with reasons and make the engineering run incomplete. Per-cohort outputs retain counts, numerator, eligible denominator, missing predictions and unscored counts; unscored rates/numerators are null. Independent metrics from all 12 frozen gates remain NOT_TESTED/null. No label or threshold is tuned after scoring.

Canonical manifests bind baseline revision, the complete application-source fingerprint, actual versions of the 39 pinned runtime distributions, candidate/gate hashes and versioned alert/dashboard hashes. Development inputs/parser/references are included in that source fingerprint. Model/prompt repetitions do not apply to this deterministic native parser. Canonical results exclude trace IDs, correlation UUIDs and measured durations; separately retained raw telemetry is linked by the canonical report hash. A complete run requires all operational controls and development conformance; omitting operations cannot produce PASS. Outputs are exclusive, private, bounded and excluded from all explicitly configured input trees.

The Stage B engineering format extends the proposed future scored-run shape: actual independent review/model/prompt fields are null, while the historical pending-template hash is recorded separately. The operational input inventory binds the exact rule manifest, specification and scenarios bytes, schema/specification/rule versions and provisional policy versions. Existing policy/index fixtures are rebuilt locally from those bound inputs and source; the index descriptor does not assert a deployed or independently approved search index. An input-byte mutation changes the inventory even if aggregate operational verdicts happen to stay the same. The full dependency inventory also has its own hash.

## Genuine SDK and safe local retention

The optional observability extra adds SDK 1.45.2; constraints pin its semantic-conventions 0.66b2 dependency and retain API 1.45.2. Private TracerProvider/MeterProvider instances use explicit synthetic resources, SpanLimits, SimpleSpanProcessor and a defensive local SpanExporter; metrics use InMemoryMetricReader, Counter, Histogram and a cardinality-limited View. No global provider, environment resource detector, periodic export thread, console/remote exporter or automatic instrumentation is configured. Actual elapsed durations are recorded by the SDK and retained in safe raw span records; canonical metric evidence keeps counter values and histogram counts rather than unstable timing aggregates.

The local sink retains at most 4,096 spans, 128 per correlation, and half of a 4 MiB budget for span records, leaving room for derived logs. The CLI separately enforces 4 MiB per serialized output. Metrics are restricted to 32 boundary/result combinations per instrument, at most 64 published points. Drops/export/instrumentation failures are bounded visible counters and invalidate complete primary trace evidence. No unbounded queue is used. Synchronous memory export is intentionally small; it is not a hard CPU/latency guarantee.

Only fixed boundary/result enums, canonical UUIDs, trace/span/parent IDs and measured durations enter retained spans. Safe logs derive from those fields. Attributes/events/status descriptions, exception messages, headers, tokens, cookies, keys, identity claims, case IDs, narratives, prompts/responses, document/evidence bodies, URLs and baggage are omitted before retention. Metrics have only boundary/result labels. A guarded exporter contains exceptions before SDK exception logging can expose their messages. Collection failures appear in the same health snapshot. Leakage tests inspect real SDK output and exception logs.

## Composition and authority

Opt-in wrappers reuse existing M12 stages, M11 reads, M13/M14 MCP SDK, M15 review, M16 API and M17 UI without changing their business code or defaults. Valid bounded W3C traceparent propagates across ASGI and fresh recovery processes; SDK-generated flags including `03` round-trip. Duplicate/malformed/zero context is ignored. Baggage and tracestate are discarded; trace metadata cannot create an authenticated session or case grant.

M20 transactional outcomes and M21 current grants are composed in disposable private stores. Synthetic publication still requires explicitly supplied same-runtime approval, independent host configuration and canonical assigned humans. No general endpoint or autonomous outcome is added. Business exceptions propagate unchanged; telemetry export failure or zero trace sampling cannot remove required SQL audit or acknowledge a failed transaction. Existing fail-closed identity logging remains unchanged. M22 telemetry is operational evidence, not the durable business audit.

## Local dashboards, faults and limits

[Versioned specifications](../../data/operations/m22/v1) define eight snapshot count panels and eight owned alerts. The executable evaluator tests each threshold and its immediately lower negative control; absent signals stay NOT_TESTED/null. Actual injected local faults supply separately reported signals. Review backlog is measured as one and remains below its threshold of two; a simulated boundary input exercises its positive condition. This is not a continuous production dashboard, a notification service or a calibrated rolling SLO.

[Runbooks](../operations/m22-runbooks.md) map each observed fault to owner and bounded response. Real workflow outages, deadlines, retry success/exhaustion, stale revisions, SQL failure, exporter failure, finite sink overflow, outbox dead-letter exhaustion, actual pre/post-commit SIGKILL and fresh-process recovery are exercised. Exactly one committed synthetic decision and five audit events survive recovery/replay; revoked duplicate access is denied while history remains. Fixed-key current-anchor rollback rejection is reused from M21. These are local process probes, not power-loss, cloud/distributed durability, live identity or host-compromise assurance.

Historical M8 failures, M12 timing sensitivity, M19 80 PASS / 0 FAIL / 8 NOT_TESTED and M20/M21 trusted-key/anchor, cross-store admission-race and same-runtime limits remain. Whole-package source changes intentionally invalidate historical workflow/store fingerprints. No migration, rehash, fallback identity, key replacement, independent approval fabrication, Azure or M23 implementation is included.

The preserved Stage A candidate-authoring namespace guard assumes a real repository `data` directory. A wheel-test topology using a symlinked repository data root exposed two failing authoring checks: the resolved destination escaped its repository-relative comparison. This pre-existing authoring alias path is outside Stage B acceptance; do not use candidate authoring with that topology. Stage B output exclusion independently uses canonical configured roots. Wheel acceptance uses byte-identical real data copies, with the two generated test directories moved out and all original data/evidence verified unchanged. Supporting aliased authoring roots requires a separate correction; these failures are retained in validation evidence rather than hidden or counted as passes.
